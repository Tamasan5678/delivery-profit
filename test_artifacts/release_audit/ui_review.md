# UI・操作性レビュー

## 画面サイズ

| 条件 | 結果 |
|---|---|
| 標準 1080×2424 | Home主要表示に崩れなし |
| 小型 720×1280 | Home上段2カードに各15px右overflow |
| 小型 + font scale 2.0 | 見出しが大きく折返し、主要情報が初期表示外。スクロール可能 |
| 大型 1440×3200 | Homeカードは正常、余白も許容範囲 |
| 横画面 | Emulator停止のため未確認。Weather固定Columnは高リスク |
| ダークモード | 未対応。light theme固定 |

## Home

- 利益、時給、平均利益、平均走行距離、平均配達時間、平均消費ガソリンを表示。
- 標準・大型ではカンマ、単位、小数桁が読みやすい。
- 小型では2列カードのタイトルRowが幅を超える。
- 上段「今日」と下段の日/週/月集計の範囲差が視覚的に弱い。
- 最重要価値の利益がカード群の一項目に見え、売上・燃料費・利益の関係が一目で伝わりにくい。

## 入力画面

- 既存監査成果物とWidgetテストでオンライン時間、売上6桁、件数2桁、距離、決定/キャンセル、0値を確認。
- pickerは決定時反映、キャンセル時維持のテストあり。
- FinishInputはスクロール可能。
- WeatherScreenはScrollViewなしのため、横画面・最大文字でボタンが画面外になるリスク。

## 結果画面

- 利益、時給、平均利益、平均走行距離、平均配達時間、平均消費ガソリンと単位を表示。
- SingleChildScrollViewで縦方向を保護。
- ホームへ戻る多重遷移防止は既存テストで確認。
- PR価値を強めるなら、利益を最上部で最大表示し、売上からガソリン代を引いた説明を隣接させる。

## 履歴

- 一覧、詳細、削除確認、戻った後の再集計を既存テストで確認。
- ListView.builderで表示Widgetは遅延生成。
- 全件DB読込のため大量件数で初期表示が劣化し得る。
- 100/500件の端末スクロール速度は未測定。

## ブランド・PR導線提案

テーマ「あなたは、この配達の利益、分かりますか？」に対して、現在は計算結果は揃っているが、問い→入力→利益発見という物語が弱い。

提案優先順:

1. Home最上部を「今日の利益」ヒーロー領域にし、利益を最も大きく表示。
2. 「売上 − ガソリン代 ＝ 利益」を3つの数値で横並び/縦並び表示。
3. 配達開始前に短い問いかけ、終了後に「売上ではなく、今日残った利益」を示す。
4. 日/週/月タブの直下へ対象期間ラベルを明示。
5. アプリアイコン・Splash・Feature Graphicを同じ利益テーマで統一。

これらは提案のみで、今回コード変更は行っていない。
