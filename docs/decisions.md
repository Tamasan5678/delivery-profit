# 設計判断

## 配達中画面は別画面にしない

配達中の情報は HomeScreen の通常モードと共通する集計情報と密接なため、別画面を増やさず HomeScreen の状態切替で表示する。これにより、配達中の目標件数・天気・終了操作を一つの起点で確認できる。

## HomeScreen をモード切替方式にする

`_isDelivering` と `DeliverySession` を HomeScreen が保持し、配達開始結果・配達終了結果に応じて表示を切り替える。現行 MVP では単純で追跡しやすい方式を優先する。

## 画面間データは Navigator の戻り値で渡す

配達開始フローは `DeliverySession`、終了フローは `FinishInputResult` を Navigator の戻り値として渡す。データ契約をモデルで明示できる一方、将来的には Repository／状態管理層へ移す。

## 現在は一時メモリ管理を基本とする

現行 HomeScreen の当日集計は State に保持する。これは MVP の画面動作確認を簡素化するためであり、再起動後も保持すべき実績データには不十分である。

## 将来 SQLite へ移行する

配達セッションを履歴として検索・集計する必要があるため、永続化の本命を SQLite とする。SharedPreferences は少量の設定値・前回値に限定し、実績履歴は SQLite に集約する。

## 入力不備は画面内で阻止する

空欄および数値として解釈できない値は保存せず、SnackBar で利用者へ通知する。保存処理中の二重実行を抑止するフラグも画面内に置く。

## 設計書を実装より先に整備する

README の開発ルールに従い、機能追加前に現行仕様・未実装範囲・将来方針を文書化する。今回の設計書作成では既存コードを変更しない。
