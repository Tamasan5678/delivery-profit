# 画面設計（現行実装）

## 対応画面方向

Delivery Profitはスマートフォンでの片手操作性を重視するため、縦画面（Portrait）のみ対応とする。横画面（Landscape）はサポート対象外とし、UI設計・テスト・品質保証も縦画面のみを対象とする。

全画面はPortraitUpを前提として設計し、Landscape専用レイアウトやLandscape向け分岐は設けない。

画面幅360dpを最低品質基準、411dpを標準、480dpを大型スマートフォン確認幅とする。Row内の文字・数値はFlexibleやFittedBoxで制約内へ収め、固定寸法へ過度に依存しない。縦方向に収まらない画面はSingleChildScrollView等で主要ボタンまで到達可能にする。文字サイズ拡大時も利益・売上等の重要情報と主要操作を失わない。

## HomeScreen

- 役割：アプリの起点。当日の集計を表示し、通常モードと配達中モードを切り替える。
- 表示項目：ロゴ、挨拶、今日の利益、今日の売上、今日の件数、オンライン時間、日別の利益・時給・平均利益／件・平均走行距離／件・平均配達時間／件・平均消費ガソリン／件。配達中は「配達中です」、目標件数、天気を追加表示。
- ボタン：通常時「配達開始」、配達中「配達終了」。下部ナビゲーション（ホーム、履歴、設定）。
- 入力項目：なし。
- 遷移先：配達開始 → StartDistanceScreen、配達終了 → FinishInputScreen、下部ナビゲーション → HistoryScreen／SettingsScreen。
- 復元：起動時に配達中一時データを読み込み、復元完了まではローディングを表示して通常モードのちらつきを防ぐ。
- 集計切替：各読込に世代番号を付け、最後に選択した日・週・月の結果とローディング状態だけを反映する。
- 遷移：配達開始、配達終了、履歴、設定は遷移中フラグで多重pushを防ぎ、遷移終了・失敗後に再操作可能とする。

## StartDistanceScreen

- 役割：配達開始時の開始走行距離を確認する。
- 表示項目：SharedPreferencesに保存した前回終了走行距離。保存値が欠損する場合はSQLiteの最新実績から復元し、初回は106,620kmとする。
- ボタン：「変更する」、「次へ」。戻るボタンあり。
- 入力項目：開始距離（6桁の桁別スクロール入力）。復元値は初期値であり、手動変更できる。
- 遷移先：次へ → TargetCountScreen。戻る → HomeScreen。

## TargetCountScreen

- 役割：当日の目標配達件数を確認する。
- 表示項目：目標件数（初期値 20件）、説明文、挨拶ヘッダー。
- ボタン：「変更する」、「次へ」。戻るボタンあり。
- 入力項目：目標件数（00～99件の2桁スクロール入力）。
- 遷移先：次へ → WeatherScreen。戻る → StartDistanceScreen。

## WeatherScreen

- 役割：当日の天気を選択し、配達セッションを開始する。
- 表示項目：晴れ、曇り、雨、選択状態チェック、挨拶ヘッダー。
- ボタン：「配達を開始する」。戻るボタンあり。
- 入力項目：天気（選択式、初期値は晴れ）。
- 遷移先：配達を開始する → HomeScreen（配達中モード）。戻る → TargetCountScreen。

## FinishInputScreen

- 役割：配達終了時の実績値を入力する。
- 表示項目：挨拶ヘッダー、入力フォーム。
- ボタン：「保存する」。戻るボタンあり。
- 入力項目：オンライン時間（例 8:00）、今日の売上（円）、配達件数、走行距離（km）。
- 入力検証：空欄は保存不可。売上・件数・走行距離は整数として解釈できない場合に保存不可。保存中の二重実行を抑止する。
- 保存：配達時点の設定値と計算結果をRepository経由でSQLiteへ保存する。成功後、結果画面へ進む前に「開始距離 + 今回走行距離」を前回終了距離として保存する。距離キャッシュだけが失敗しても実績を再INSERTせず、次回は最新SQLite実績から復元する。設定値不正時またはSQLite保存失敗時は入力値を維持して画面に留まり、SnackBarを表示して再試行可能とする。
- 遷移先：保存成功 → 本日の配達結果画面。戻る／保存失敗 → FinishInputScreen に留まる。

## 本日の配達結果画面

- 役割：保存直後に本日の主要な計算結果を確認する。
- 表示項目：利益、時給、平均利益／件、平均走行距離／件、平均配達時間／件、平均消費ガソリン／件。
- 計算：DeliveryCalculator を利用する。平均走行距離／件は合計走行距離 ÷ 配達件数とし、0件の場合は 0.0km／件とする。週別・月別も、期間内の合計走行距離 ÷ 期間内の合計配達件数で算出する。
- ボタン：「ホームへ戻る」。
- 遷移先：ボタンまたは端末の戻る操作 → 当日データを保持した HomeScreen（通常モード）。FinishInputScreen へは戻らない。

## HistoryScreen

- 役割：SQLiteの完了済み配達履歴を終了日時の新しい順で一覧表示する。
- 操作：履歴カードをタップするとHistoryDetailScreenへ遷移する。詳細で削除された場合は一覧を再読込する。
- 空表示：「配達履歴はまだありません」。

## HistoryDetailScreen

- 表示項目：配達日、開始／終了日時、目標件数、天気、オンライン時間、売上、件数、距離、燃費、ガソリン単価・使用量・代金、利益、時給、各1件平均。
- 削除：「この記録を削除」から確認ダイアログを表示し、「削除する」で対象1件だけをRepository経由で削除する。連打中は操作を無効化する。
- 成功時：`true`を戻してHistoryScreenを再読込し、完了SnackBarを表示する。失敗時：詳細画面に留まり、再試行可能なSnackBarを表示する。
- 履歴削除は収支履歴だけを対象とし、現在の車両総走行距離として保存した前回終了距離は変更しない。

## SettingsScreen（現状）

- 役割：利益計算に使用する車両設定を編集する。
- 表示項目：車両設定、平均燃費、ガソリン単価。
- 入力項目：平均燃費（1.0～50.0km/L、0.1刻み）、ガソリン単価（100～300円/L、1円刻み）。既存のスクロール入力を使用する。
- 保存：変更決定時に SharedPreferences へ保存し、アプリ再起動後も復元する。
- 遷移：HomeScreen 下部の「設定」から表示し、戻ると設定値を再読込した HomeScreen を表示する。

## Delivery Profit 入力UI共通ルール

### 入力方式

- 開始走行距離：桁別スクロール入力。単位は km。
- 終了走行距離：桁別スクロール入力。単位は km。
- 今日の売上：6桁の桁別スクロール入力。入力範囲は 000000～999999円。不要な先頭ゼロは薄いグレーで表示し、確認表示はカンマ付き金額を優先する（例：001200 → 1,200円）。
- 今日の目標件数：2桁の桁別スクロール入力。入力範囲は 00～99件。
- 配達件数：2桁の桁別スクロール入力。入力範囲は 00～99件。
- オンライン時間：時間と分の2列スクロール入力。時間は 0～23、分は 0、5、10、……、55。
- 天気：現在のボタン選択方式を維持する。
- 平均燃費：スクロール入力。1.0～50.0km/L、0.1刻み。
- ガソリン単価：スクロール入力。100～300円/L、1円刻み。

### 共通動作

- 入力欄をタップすると画面下からモーダル表示する。
- 現在値を初期位置にする。
- 「決定」でのみ反映する。
- 「キャンセル」または画面外タップでは元の値を維持する。
- 原則として数字キーボードは表示しない。
- 小さい端末でも文字切れやはみ出しが起きないこと。
- 入力値と保存値を一致させる。
